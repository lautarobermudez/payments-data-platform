# Contributing

This is a portfolio project, but it is kept like a real one.

- **Branches:** work on a feature branch and open a pull request into `main`; CI must be green.
- **Commits:** short imperative subject (`Add cost-centre trigger`), one logical change each.
- **Database changes:** add a new numbered script in `db/` instead of editing an applied one, and cover the new rule with a query in `db/tests/data_quality.sql`.
- **Data:** never commit real data. Everything under `seed/data/` and `seed/deltas/` is generated by `seed/generate_seed.py` (CI fails if the committed files differ from a fresh generation).
- **Checks before pushing:** `make test` (unit tests, data-quality rules, integration and API tests; needs the database from `make up init load load-deltas`). To see everything working end to end: `make demo`.
- **Audited tables:** a new table that holds business data should get the `trg_audit` trigger in `db/05_audit.sql`; anything the API serves must be reachable through a view that leaves out bank details (`db/06_api_role.sql`).
